## Описание задания: Тестирование сервера «Поиск кафе»

В этом проекте вам предстоит написать тесты для уже существующего HTTP-сервера, который возвращает список кафе по заданным параметрам. Вы уже знакомы с сервером из предыдущего урока, и ваша задача – проверить корректность его работы при различных значениях GET-параметров `count` и `search`. Это позволит убедиться, что сервер правильно фильтрует и ограничивает количество выдаваемых результатов, а также корректно выполняет поиск по подстроке.


## Описание сервера

Сервер имеет единственный эндпоинт `/cafe`, который принимает три параметра:

- **`city`** (обязательный) – название города. Поддерживаются только `moscow` и `tula`.  
- **`count`** (необязательный) – количество возвращаемых кафе. Если не указан или превышает число доступных кафе, возвращаются все кафе города.  
- **`search`** (необязательный) – строка для поиска в названии кафе. Поиск выполняется без учёта регистра. Возвращаются только те кафе, в названии которых встречается переданная подстрока.

Ответ сервера представляет собой строку, в которой названия кафе разделены запятыми (например, `"Пир и мир, Красиво есть не запретишь, Поздний завтрак"`).

В коде сервера уже имеются проверки на корректность города и обработка ошибок, но функциональность работы с `count` и `search` тестами не покрыта. Ваша задача – написать недостающие тесты.


## Цель задания

Написать две тестовые функции в файле `main_test.go` (которые уже должны быть начаты) и убедиться, что сервер:

1. Ограничивает количество выдаваемых кафе в соответствии с параметром `count`.  
2. Правильно фильтрует кафе по подстроке, переданной в `search`, и возвращает только те, что содержат эту подстроку (без учёта регистра).

При этом вы должны использовать пакеты `assert` и `require` из библиотеки `testify` для проверок.


## Структура проекта

- **`main.go`** – содержит код сервера.  
- **`main_test.go`** – содержит тесты. В нём уже должны присутствовать две функции (из предыдущих уроков):
  - `TestCafeWhenOk()` – проверяет успешный запрос с корректным городом.  
  - `TestCafeNegative()` – проверяет негативные сценарии (некорректный город, отсутствие параметра `city`).  
- Вам нужно добавить ещё две функции:
  - `TestCafeCount()` – для проверки параметра `count`.  
  - `TestCafeSearch()` – для проверки параметра `search`.


## Требования к каждой тестовой функции

### 1. Функция `TestCafeCount()`

**Цель:** проверить, что сервер возвращает ровно столько кафе, сколько указано в `count` (или все, если запрошено больше, чем есть).

**Действия:**
- Отправить запросы к `/cafe` с разными значениями `count` (0, 1, 2, 100).
- Для каждого запроса получить ответ, разделить его по запятой в слайс строк (используя `strings.Split`), подсчитать количество элементов.
- Сравнить фактическое количество с ожидаемым.
- Для эталонного количества кафе в городе использовать глобальную переменную `cafeList` (она доступна в тестах, так как тесты находятся в том же пакете). Получить длину списка для выбранного города (например, для Москвы).

**Рекомендуемый подход:**
- Использовать тестовую таблицу (slice структур) с полями `count` и `wantCount`.
- Для каждого случая отправлять запрос, проверять статус код с помощью `require.Equal` (чтобы гарантировать успешность), а затем с помощью `assert.Equal` сравнивать полученное количество с ожидаемым.


### 2. Функция `TestCafeSearch()`

**Цель:** проверить, что сервер возвращает только те кафе, в названии которых встречается указанная в `search` подстрока (регистронезависимо).

**Действия:**
- Отправлять запросы с параметром `search` и городом `moscow`.
- Проверять, что все возвращённые кафе содержат искомую подстроку (использовать `strings.Contains` с приведением к одному регистру).
- Также проверять количество найденных кафе (ожидаемое число известно заранее).

**Тестовые случаи:**
- `search=фасоль` – ни одного кафе (0 результатов).
- `search=кофе` – два кафе.
- `search=вилка` – одно кафе.

**Рекомендуемый подход:**
- Тестовая таблица с полями `search` и `wantCount`.
- Для каждого запроса проверять статус код (require), а затем:
  - Разбить ответ на слайс.
  - Проверить длину слайса (assert).
  - Для каждого названия проверить, что оно содержит подстроку (assert) – например, через цикл.


## Использование библиотеки `testify`

- `require.Equal(t, expected, actual, msg)` – используется для критических проверок (например, статус код). При неудаче тест сразу завершается.
- `assert.Equal(t, expected, actual, msg)` – используется для проверок, которые не должны прерывать выполнение остальных проверок в том же тесте (можно использовать для сравнения количества и содержания).
- Также можно использовать `assert.Contains` или другие удобные функции.


## Итоговый результат

После написания тестов выполните команду `go test .` в корне проекта. Все четыре тестовые функции должны выполняться успешно (без ошибок). В итоге файл `main_test.go` должен содержать следующие функции:

- `TestCafeWhenOk()`
- `TestCafeNegative()`
- `TestCafeCount()`
- `TestCafeSearch()`
